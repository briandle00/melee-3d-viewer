The GX player's simulator module (gx-core.js, gx-core.wasm) and its game file list (sim-files.json).

Built from melee-sim-light (https://github.com/briandle00/melee-sim-light, a fork of https://github.com/kyhavlov/melee-sim-light),
branch sound/w41 at 0b6fd0c6 (local; on perf/open 7018279c: the float rule for a sum's own product, native libm calls, fighter facing in
the effect callback): the viewer build with the HUD layout option (msl_gxw_set_hud_layout), the stream restart and memory-top
calls the app's player seeks with (msl_gxw_restart_stream, msl_gxw_heap_top), the game data load kept for the next match
(msl_gxw_load_game, msl_gxw_rewind: a restart or a C-stick fit drive opens in milliseconds), and the sound core (src/sound: the game's
own sound code, off unless the page starts it: msl_gxw_sound_start, msl_gxw_sound_need, msl_gxw_sound_pcm, msl_gxw_sound_frames,
msl_gxw_sound_music, msl_gxw_sound_info, msl_gxw_sound_log, msl_gxw_sound_log_count); the browser build computes no game data
fingerprint (it only marks a saved state's game data). Built with tools/build/build_wasm_gx.sh, DATA unset: no game data is inside the
module (the page hands it the user's own files, main.dol included; the sound files only when sound is on).
Source-file names are relative (prefix maps); gx-core.js is written with LF line ends.

sha256
  gx-core.js    9256557cdc6809a3a0522027a3078dd7670e6e9f68542687fb1657e31d8122ba
  gx-core.wasm  3581b3676303ac8cc2f48a183f696a43ee878d25e5ba5d67a3d9678b70dd345b

sim-files.json lists the game files the module reads (names only), for a game folder given by URL (?files=). The sound files are not in
it: the module names them when the sound starts (audio/us/smash2.sem, the match's audio/us/*.ssm banks, the stage's audio/*.hps).
